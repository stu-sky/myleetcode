# 102. 二叉树的层序遍历

**代码**：[codes/0102-binary-tree-level-order-traversal.go](../codes/0102-binary-tree-level-order-traversal.go)

## 一分钟复习

- 识别信号：逐层、从左到右，结果按层分组。
- 核心方法：BFS + 队列，先入先出。
- 不变量：每轮外层循环开始，队列恰好存着当前层的全部非空节点，顺序从左到右。
- 划层关键：先固定 `size := len(queue)`，内层只处理 size 次，孩子留到下一轮。
- 结果组织：`res` 是二维切片，`level` 是本层的一维切片；每处理完一层再追加到 res。
- 复杂度：时间 O(n)，额外空间 O(w)，返回结果空间 O(n)，w 为最大层宽。

## 题目

给定二叉树根节点 `root`，返回按层分组的节点值：层与层之间从上到下，每层内部从左到右。

- 输入：根节点 `root`。
- 输出：二维整数数组，每个内层数组对应一层。
- 示例 1：`root = [3,9,20,null,null,15,7]`，输出 `[[3],[9,20],[15,7]]`。
- 示例 2：`root = [1]`，输出 `[[1]]`。
- 示例 3：`root = []`，输出 `[]`。
- 约束：节点数 0～2000，节点值 -1000～1000。

来源：[LeetCode 102](https://leetcode.cn/problems/binary-tree-level-order-traversal/)。输入数组是树的层序表示，null 表示缺失的节点。

## 怎么想到

题目不是只要求访问所有节点，还要求按层输出。朴素地对每个深度都从根重新搜索，会重复访问上层节点，链状树最坏需要 O(n²)。我们希望保留下一层的待访问节点，而不是重新从根寻找。

**队列**是先入先出的容器：从队头取节点，把孩子加入队尾。**BFS（广度优先遍历）**优先处理距离根更近的节点；本题通过队列让当前层先处理完，再处理下一层。

但队列只保证访问顺序，不会自动给结果划层。解决办法是在每层开始时固定队列长度：此时队列里的都是当前层节点，只处理这些节点，就能得到一行结果。

## 核心不变量

每轮外层循环开始时，queue 恰好包含当前层全部非空节点，并按从左到右排列。内层处理期间，队列前部是当前层尚未处理的节点，后部是已经发现的下一层节点；处理 size 次后，只剩下一层。

## 算法步骤与 Go 切片含义

1. 创建空结果；空树直接返回。
2. 根节点入队。
3. 队列非空时，固定当前层长度 size，创建新的 level。
4. 出队 size 次：记录节点值，先把非空左孩子入队，再把非空右孩子入队。
5. 将完整的 level 追加到 res，进入下一层。

```go
res := make([][]int, 0)          // 长度为 0：还没有任何一层。
level := make([]int, 0, size)    // 长度为 0，容量为 size，后续追加本层的值。
level = append(level, node.Val) // 一个节点的值加入本层。
res = append(res, level)        // 完整的一层加入最终结果。
```

这里用 append 增加元素，不是直接写 `res[0]` 或 `level[0]`。注意 `make([]int, size)` 会预先产生 size 个零值元素；若继续 append，就会把实际值接在这些零后面。

## 执行过程

```text
      3
     / \
    9  20
       / \
      15  7
```

| 层开始时的队列 | 固定 size | 本层 level | 层结束时的队列 |
| --- | ---: | --- | --- |
| [3] | 1 | [3] | [9,20] |
| [9,20] | 2 | [9,20] | [15,7] |
| [15,7] | 2 | [15,7] | [] |

第一轮处理 3 后，队列已有 9、20，但 size 固定为 1，所以内层立即结束。它们不会混进第一行结果。

## 正确性解释

初始只有根节点，符合第一层的不变量。每层固定处理 size 个节点，孩子加入队尾，不会提前处理；父节点按从左到右出队，每个父节点又先加入左孩子、再加入右孩子，因此下一层仍然从左到右。每层结束只剩下一层节点，不变量继续成立，最终每个节点被记录在正确的层中。

## 复杂度

- 时间 O(n)：每个节点入队、出队一次；切片追加摊还为 O(1)。`queue = queue[1:]` 只是调整切片视图，不会搬移剩余元素。
- 额外空间 O(w)：队列和本层切片最多保存 O(w) 个元素；处理期间队列可能混有相邻两层，但仍是 O(w)。最坏 w 为 O(n)。
- 返回结果占 O(n) 空间；若计入输出，总空间为 O(n)。

## 易错点

- **错误想法：内层用 `i < len(queue)`。** 为什么会错：出队和孩子入队都会改变长度，无法保证只处理当前层；必须提前固定 size。
- **错误想法：所有节点值直接追加到 res。** 为什么会错：res 的元素类型是 `[]int`，题目也要求按层分组；应先填 level，再整层追加。
- **错误想法：把 nil 孩子也入队。** 为什么会错：本题只输出实际节点值，访问 nil 的 Val 会 panic；与 101 对称二叉树不同，这里不需要保留空位置来比较结构。

## 自测

1. 为什么每层开始的队列长度可以作为这一层的节点数？
2. 处理当前层时队列里会不会出现下一层节点？为什么它们不会被提前处理？
3. `make([]int, 0, size)` 和 `make([]int, size)` 在继续 append 时有什么区别？
4. 不看代码，能否写出“固定层长 → 出队记录 → 孩子入队 → 整层追加”的循环？
5. 如果每层只要最右边节点，应在本层的哪个位置记录答案？
