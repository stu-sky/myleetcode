# 543. 二叉树的直径

**代码**：[codes/0543-diameter-of-binary-tree.go](../codes/0543-diameter-of-binary-tree.go)

## 一分钟复习

- 识别信号：任意两点之间的最长路径，不一定经过根。
- 核心方法：后序遍历，先得到左右子树深度，再处理当前节点。
- 核心不变量：`depth(node)` 返回从当前节点向下的最长单链节点数，空节点返回 0。
- 两个结果：返回值是当前节点的深度；外部变量 `ans` 是遍历过程中发现的最大直径，两者不是同一个量。
- 关键操作：更新答案选两边 `left + right`；返回父节点选一边 `1 + max(left, right)`。
- 复杂度：时间 O(n)，递归栈空间 O(h)，最坏 O(n)。

## 题目

给定二叉树根节点 `root`，求任意两个节点之间最长路径的长度，长度按**边数**计算。路径可以经过根节点，也可以完全位于某棵子树内部。

- 输入：二叉树的根节点 `root`。
- 输出：最长路径的边数。
- 示例 1：`root = [1,2,3,4,5]`，输出 `3`，对应路径 `4 → 2 → 1 → 3`。
- 示例 2：`root = [1,2]`，输出 `1`。
- 约束：节点数为 1～10000，节点值为 -100～100；节点值不影响路径长度。

来源：[LeetCode 543](https://leetcode.cn/problems/diameter-of-binary-tree/description/)。数组示例采用层序表示。

## 怎么想到

题目要求任意两点的最长路径，不能只考虑根到叶子。朴素做法是在每个节点重新计算左右子树深度，取两者之和的最大值；深度会被反复计算，链状树最坏达到 O(n²)。

值得复用的信息是：**每棵子树向下的最长单链深度**。父节点只需要左右子树各返回一个深度，就能计算经过自己的最长路径，无需重新扫描子树。

后序遍历是“左子树 → 右子树 → 当前节点”的处理顺序。本题用它让子树先交出深度，再由当前节点计算答案；递归调用栈保存尚未完成的父节点。

### 先拆开理解：求深度与求直径

**第一件事：求当前节点的深度。** `depth(node)` 回答“从当前节点向下走，最长能经过多少个节点”。空节点是 0，叶子是 1；拿到左右深度后，选择较长的一边，再加当前节点：`1 + max(left, right)`。

**第二件事：检查经过当前节点的最长路径。** 这次允许从左边走上来，再走到右边，因此两边都要选：节点数为 `left + right + 1`，边数为 `left + right`。你想到的“左右相加再加 1”没有错，只是统计的是节点数，而本题要求边数。

例如左深度为 2、右深度为 1：当前节点的深度是 3 个节点；经过当前节点的路径有 4 个节点、3 条边。

### 为什么在 depth 里面更新 ans？

每个节点都可能是最长路径连接左右两边的位置，因此需要检查所有节点。`depth` 在每个节点恰好已经算出了左右深度，这时顺便更新 `ans`，可以避免另一次遍历和重复计算。

所以这个函数有**两项职责，但只有一个返回值**：

| 信息 | 回答的问题 | 传递方式 |
| --- | --- | --- |
| 返回值 | 从当前节点向下，最长的一条链有多少节点？ | `return` 交给父节点 |
| `ans` | 所有已经检查过的节点中，最长路径有多少条边？ | 更新外部变量，不作为递归返回值 |

Go 中这里的匿名函数能访问并修改外层的 `ans`，这种引用外部变量的函数称为**闭包**。执行 `depth(root)` 是为了遍历并更新答案；最外层最终返回的是 `ans`，不是根节点的深度。

## 核心不变量

`depth(node)` 返回从 `node` 向下走、不分叉的最长链的节点数。`ans` 始终是所有已检查节点的双侧路径边数的最大值；完成根节点的处理后，就得到整棵树的直径。

## 算法步骤

1. 空节点返回深度 0。
2. 递归求左右子树深度 `left`、`right`。
3. 用 `left + right` 更新直径。
4. 返回 `1 + max(left, right)`，让父节点继续延伸单链。

## 执行过程

```text
      1
     / \
    2   3
   / \
  4   5
```

| 当前节点 | 左深度 | 右深度 | 经过它的路径边数 | 返回深度 |
| --- | ---: | ---: | ---: | ---: |
| 4、5、3 | 0 | 0 | 0 | 1 |
| 2 | 1 | 1 | 2 | 2 |
| 1 | 2 | 1 | 3 | 3 |

最终直径为 3。注意根节点返回的深度也恰好是 3，但这只是巧合：深度和直径是两个不同的量。

## 正确性解释

任意路径都有一个最高节点，在该节点处可拆成左右两条向下的链；某一边也可以为空。左右各选最长链，就得到经过该节点的最长路径。遍历所有节点取最大值，因此也能发现不经过根的直径。

为什么返回值只能选一边？返回值需要继续连接父节点；若同时保留左右两边，再连接父节点会出现三岔，不再是一条合法路径。

## 复杂度

- 时间 O(n)：每个节点只处理一次，每次做常数次运算。
- 空间 O(h)：来自递归调用栈；平衡树为 O(log n)，链状树为 O(n)。

## 易错点

- **错误想法：只计算根节点的左右深度之和。** 为什么会错：最长路径可能完全位于一侧子树，必须在每个节点更新答案。
- **错误想法：返回 `left + right + 1`。** 为什么会错：这是经过当前节点的双侧路径节点数，不能作为向父节点延伸的单链。
- **错误想法：直径也要加 1。** 为什么会错：题目统计边数，`left + right + 1` 统计的是节点数；单节点树的直径应为 0。

## 自测

3. 为什么算法能找到完全不经过根节点的最长路径？
